# NexusHub 核心功能缺口与开发前方案

## 1. 结论与范围

现有需求、接口和表模型已经覆盖斗地主规则、双人明牌对局以及求解器边界；实现前仍需要把账号安全、题目版本生命周期、分析任务可视化、门户入口配置、审计和桌面端状态统一成可验收的工作流。本方案只覆盖桌面端 1440px 基准及 768px 折叠，不设计移动端交互；OpsDesk 当前只作为独立外链，不代理其业务。

本轮实现目标是“登录后可用的斗地主实验室”：用户登录、浏览已发布残局、创建自己的残局草稿、提交不可变版本、管理员发布/归档、创建对局或分析任务、查看严格证明和最多五条已验证路线。所有状态均以服务端返回为准。

## 2. 功能模块与职责边界

| 模块 | 本轮必须交付 | 服务端职责 | 前端职责 |
|---|---|---|---|
| identity | 登录、退出、当前用户、管理员账号启停/重置 | Cookie 会话、CSRF、密码哈希、限流、权限和会话失效 | 登录表单、会话过期、无权限和账号状态 |
| hub | 门户首页、斗地主入口和 OpsDesk 外链 | 卡片目标互斥且外链不泄漏会话 | 卡片、空入口、加载/失败重试；OpsDesk 外链可用 |
| puzzle | 公共题库、我的草稿、版本编辑/校验/发布/归档/复制 | 对象授权、不可变版本、rowVersion、发布原子切换 | 筛选、编辑器、字段错误、版本冲突、发布确认 |
| game | USER/BOT 双人明牌、可选先手、行动和复盘 | 合法行动、状态转移、机器人行动、快照和行动幂等 | 牌桌、可出牌提示、PASS 原因、机器人思考、结束态 |
| analysis | 异步分析、取消、重试、结果和策略树 | 队列租约、预算、CAS 终态、证明 verifier、五路线稳定排序 | 任务进度、PROVEN/UNKNOWN、树懒加载、资源原因 |
| audit | 关键写操作可追溯 | 记录操作者、动作、资源、结果、requestId；脱敏 | 管理员查看筛选结果（如最终权限开放） |

Controller 只负责传输和入口校验；Service 负责事务、状态机、权限和幂等；Mapper 只负责 SQL。规则、合法行动、状态转移和证明校验保持纯 Java，不依赖 Spring、数据库或 HTTP。

## 3. 登录与权限方案

### 3.1 登录流程

1. 未登录访问受保护路由时跳转 `/login?returnUrl=...`，不把凭证或 Token 放入 URL。
2. 页面先调用 `GET /api/auth/csrf`，登录 POST 携带 CSRF Token 和幂等 Key。
3. 成功后服务端轮换会话 ID，返回当前用户摘要；前端再请求 `/api/auth/me` 和门户入口。
4. 登录失败统一显示“用户名或密码错误”；账户不存在、停用和密码错误不能通过文案或耗时枚举。
5. 退出、停用、重置密码后清空 Pinia 用户状态并重新获取 CSRF；会话过期统一回到登录页。

### 3.2 权限矩阵

| 能力 | 匿名 | USER | ADMIN |
|---|---:|---:|---:|
| CSRF/登录 | ✓ | ✓ | ✓ |
| 门户/已发布题库 | - | ✓ | ✓ |
| 自己的草稿和版本 | - | ✓ | ✓ |
| 发布、归档、恢复 | - | - | ✓ |
| 创建对局/分析 | - | ✓ | ✓ |
| 读取自己对局/任务 | - | ✓ | ✓ |
| 账号与系统入口配置 | - | - | ✓ |

前端路由 meta 只用于体验，Controller 和 Service 必须再次校验权限与对象所有权。私有资源不存在或无权访问统一返回 404。首个管理员通过部署命令从环境或交互输入创建，不提供匿名初始化接口，也不写默认密码。

## 4. 残局发布与版本方案

`puzzle` 是生命周期和指针；`puzzle_version` 是不可变内容。编辑已发布题目时，保留线上 `publishedVersionId`，创建或继续编辑新的草稿版本。发布请求携带 `versionId + expectedRowVersion`，事务内校验仍是当前草稿后原子切换公开指针。归档不删除版本，恢复回到 DRAFT 并清空公开指针。

发布前必须通过服务端规则校验：双方非空、先手最多 20 张、后手最多 17 张、同点数最多 4 张、当前牌墩和行动者可达；四带二不属于 CLASSIC_V1，其他牌型按标准规则固定可用。发布不要求已证明，题库可显示 UNKNOWN。

桌面端状态必须覆盖：DRAFT、待发布、PUBLISHED、ARCHIVED、版本冲突、字段错误、保存中、发布确认、发布失败。发布后编辑入口文案为“创建新草稿”，避免误以为修改线上版本。

## 5. 分析任务与策略证明方案

任务创建立即返回 `SolveTask`，搜索在 Worker 中执行。任务状态：`QUEUED → RUNNING → COMPLETED/FAILED`，QUEUED/RUNNING 可 CANCELLED；租约失效可重新排队，超过重试次数 FAILED。Worker 只有在状态为 RUNNING 且 leaseToken 匹配时才能 CAS 提交结果。

结果分三层表达：

- `proofStatus=PROVEN`：根节点有严格值，且对手所有合法应对都完成覆盖；才显示 winnerSide 和“必胜”。
- `proofStatus=UNKNOWN`：预算截断、资源不足或搜索失败，winnerSide/proofValue 必须为空；可显示基于当前预算的候选建议。
- `strategyStatus=PARTIAL/COMPLETE`：只描述材料完整度；COMPLETE 还必须通过独立 verifier。示例路线不是证明。

证明 DAG 可以包含任意数量分支，接口按稳定排序最多返回 5 条已验证路线；其余分支通过 `children` 分页或懒加载查看。前端必须区分“根结论”“路线示例”“覆盖率”和“资源原因”，不能把路线数量当作证明强度。

桌面端任务状态：排队中、计算中（进度不确定时显示已用时间/节点而非伪造百分比）、已证明、尚未证明、失败、已取消、过期。机器人提示沿用同一证明语义：未 PROVEN 时只能标为建议。

## 6. 门户与管理配置

门户只返回当前用户可见卡片。V1 注册 `LANDLORD_PUZZLE` 内部入口（目标 `/landlord/puzzles`）和 OpsDesk 外部入口（构建配置默认 `https://www.xmxisme.com/opsdesk/`）；不探测健康、不代理业务、不转交会话。管理入口配置页保留字段模型：name、description、iconKey、entryType、route/externalUrl、visibleRoles、sortOrder、enabled、rowVersion。

内部 route 与 EXTERNAL URL 互斥；未来启用外链时只允许部署白名单来源，新标签打开并设置 noopener/noreferrer，不转交 NexusHub Token。保存入口使用 rowVersion，冲突时重新加载并要求用户选择。

## 7. 审计与安全留痕

至少审计：登录成功/失败（脱敏）、退出、账号创建/启停/重置密码、草稿保存、版本发布/归档/恢复、对局创建/结束/放弃、分析创建/取消/终态提交、系统入口配置。字段包括 operatorId、action、resourceType、resourceId、result、requestId、occurredAt、sourceIp（按部署合规要求）、metadata 摘要。

审计不可写入密码、Cookie、CSRF Token、完整手牌或会泄漏私有策略的原始 payload；领域快照留在业务表。审计写入失败应按动作重要性配置：账号和发布动作失败则拒绝提交，普通读取不因审计故障阻塞；具体策略在后端实现时固定并测试。

## 8. 桌面端页面与状态清单

| 页面 | 主画面 | 必备状态/交互 |
|---|---|---|
| `/login` | 深色科技感登录卡 | 提交中、凭证错误、账户停用、会话过期、CSRF/网络失败 |
| `/` | 系统卡片门户 | 加载、无入口、请求失败重试、斗地主可用、OpsDesk 外链 |
| `/landlord/puzzles` | 题库/我的草稿 | tab、搜索筛选、分页、空结果、无权限、加载骨架、失败重试 |
| `/landlord/puzzles/new`、`/:id/edit` | 双人手牌编辑器 | 牌数校验、重复牌、四带二固定不可出、先手、当前牌墩、保存、版本冲突 |
| `/landlord/games/:id` | 双人明牌牌桌 | USER/BOT、先手选择、首手禁止 PASS、后续 PASS、合法动作、机器人思考、胜负/放弃 |
| `/landlord/games/:id/replay` | 复盘 | 逐手导航、牌墩、行动事件、终局摘要 |
| `/landlord/analysis/:id` | 证明结果 | 排队、运行、PROVEN、UNKNOWN、FAILED、CANCELLED、五条路线、树分页 |
| `/admin/systems` | 入口配置 | 启用/禁用、内部路由、外链白名单、rowVersion 冲突（动态管理仍待实现） |
| `/admin/users` | 账号管理 | 创建、启停、重置确认、最后管理员保护、分页/筛选 |

共享组件至少需要 `AppShell`、`DataTable`、`FieldErrorList`、`StatusBadge`、`Skeleton`、`EmptyState`、`ErrorRetry`、`ConfirmDialog`、`Toast`、`PokerCard`、`TaskProgress`、`StrategyTree`、`AuditSummary`。组件状态用文字和图标共同表达；焦点环、禁用原因、键盘操作必须在桌面设计中标出。

视觉方向沿用现有暖白画布和深蓝/青绿色令牌，在门户、登录和分析页增加深色渐变、细网格、低饱和荧光青强调线和轻量玻璃面板；科技感只用于层次和状态，不牺牲文字对比度和表单可读性。1440px 为验收基准，768px 仅折叠侧栏和压缩两栏布局。

## 9. 开发顺序与验收门槛

1. 先冻结 OpenAPI、状态枚举、错误码和 SQL 迁移；旧三人字段仅允许留在历史文档，不得进入实现。
2. 建立纯 Java 规则/牌型/状态转移/证明 verifier 单测，再做登录和题库版本服务。
3. 完成 Vue AppShell、登录守卫、题库和编辑器，再接对局快照和行动幂等。
4. 接入持久任务 Worker、预算、租约和证明结果，最后做策略树懒加载。
5. 每个阶段通过 `mvn clean test`、`npm run build`，同时校验 OpenAPI JSON、SQL 迁移、状态机和本方案页面状态。

## 10. 当前缺口与决策记录

- OpsDesk 当前仅配置门户外链 `https://www.xmxisme.com/opsdesk/`；SSO、健康检查、代理和数据库接入继续延后，任何实现不得假设其内部接口可用。
- 不做移动端交互和页面；文档中的旧移动端条目应移除或标为后续非本轮范围。
- 现有 Figma 已补充 Login、States & Components 桌面页；发布/版本、分析任务终态、题库空/失败、管理员用户操作等状态已作为桌面状态样板，后续实现时保持节点与契约同步。
- 初版不在 UI 展示求解性能指标；后端可记录节点数和耗时用于排障，但不作为产品页面验收项。
- 账户首个管理员初始化方式已确定为部署命令/交互输入；不应继续作为产品确认项。
