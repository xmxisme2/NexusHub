# 残局与版本模块

题库与详情按当前展示版本读取真实证明结果，PROVEN 显示“已证明 · 用户必胜/机器人必胜”，UNKNOWN 显示“尚未证明”且胜方为空；草稿、已删除等生命周期标签与证明状态独立。

| 编号 | 需求 | 验收 |
|---|---|---|
| PUZ-01 | 已发布题库与我的题目两种列表 | 普通用户看不到他人草稿；标题、标签、难度过滤 |
| PUZ-02 | 编辑基本信息、两家手牌和轮次 | 先手/后手牌量、超额牌数、无效牌型定位字段错误；四带二不可选 |
| PUZ-03 | 校验并保存不可变版本 | 保存再次服务端校验；前端 validate 结果不能代替保存校验 |
| PUZ-04 | 管理员发布指定当前草稿版本 | 不要求已证明，未证明标签保持 UNKNOWN |
| PUZ-05 | 管理员归档/恢复 | 归档禁止新开局和新分析；已有快照仍可查看/继续 |
| PUZ-06 | 复制可读版本为自己的新题目 | 新 ID、新所有者、DRAFT，无公开指针 |
| PUZ-07 | 管理员逻辑删除残局 | 只更新 `puzzle.deleted=1` 并标记 `ARCHIVED`，版本、对局快照和证明结果保留 |
| PUZ-08 | 新残局重复局面检测 | 保存前按完整初始局面做结构化匹配，包含已删除记录；命中已删除记录时返回原题目标题、版本和可复用的证明引用，不新建版本 |

`puzzle` 只保存生命周期、所有者与版本指针；标题、说明、标签、人工难度、局面都在 `puzzle_version` 中不可变存储。这样编辑后的标题不会提前泄漏到公开题库。

`scope=PUBLISHED` 查询公开指针，`scope=MINE` 查询本人最新版本，`scope=MANAGE` 仅管理员。详情请求支持 versionId；省略时，所有者/管理员看最新版本，其他人看公开版本；他人不能读取过去被撤下或未发布版本。

发布只接受 `latestVersionId`，成功原子切换 `publishedVersionId`。删除是逻辑删除：保留版本用于历史对局和证明复用，仅将题目标记为 `ARCHIVED`/`deleted=1`，普通题库查询不再展示。每次修改采用 rowVersion；保存首次无 puzzleId，后续必须提供 puzzleId 和 expectedRowVersion。新建或保存前必须执行重复局面检查，检查范围包含 `deleted=0/1` 的题目版本。

规则配置固定 CLASSIC_V1，不允许保存无法定义胜负语义的状态。难度 EASY/MEDIUM/HARD 为人工标签，与算法已证明状态不同。

数据：puzzle、puzzle_version；API：[puzzle](../../api/puzzle.md)。

残局库整张卡片作为详情链接，点击标题、手牌或卡片留白均进入详情，不再提供独立“查看局面”按钮；支持 Tab 聚焦、Enter 打开和链接的新标签页操作。

详情页提供带左箭头的“返回残局库”按钮，加载中和失败时也可返回。管理员可在最新草稿详情点击“发布残局”，成功后按接口返回更新状态和版本；普通用户显示联系管理员发布的说明。发布期间禁止重复提交及并行删除/恢复；失败保留草稿并提供刷新状态入口。
